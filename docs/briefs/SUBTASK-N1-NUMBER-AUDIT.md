## 0 · 为什么这件事值钱

这个仓库的立身之本是「所有结论都有实测出处」。那么**引错自己的数据是最伤的一种错** ——
它同时否定了结论和方法论。

已经抓到三处（都已修，作为你要找的那类错误的样例）：

| 位置 | 错的 | 对的 | 怎么发现的 |
|---|---|---|---|
| `harness/config.py` 注释 | `<200ms 0/53，300–500ms 50%` | `0/67`、`47%` | 和 `E16-DOSE-RESPONSE.md` §2 分桶表对不上 |
| `harness/README.md` | `selftest 61 条` / `46 条` | 79 条 | 实际跑一遍 |
| `docs/ARCHITECTURE.md` §1 | `归还只能降低概率（3 次仍破 1 次）` | E11 的 `0/20` | 引的是被 E11 取代的 E10 的 n=3 |

**第三个是最危险的形态**：它不是笔误，是引了一个**已经被自己后续实验推翻**的数字，
而且方向上**低估了自己的结果**。你要找的主要是这一类。

## 3 · 什么算「量化断言」

要审的：

- 次数与比例：`0/20`、`5/30`、`47%`、`8/8`、`120 键中 56 键`
- 时间：`12ms`、`2526ms`、`871ms`、`约 100s`
- 计数：`79 条测试`、`15 条 JVM 单测`、`~400 行 Kotlin`、`n≥20`
- 阈值与常量：`DISTURB_BUDGET_MS = 500`、`MAX_STEPS = 25`、`深度上限 25`
- 版本与环境：`API 34`、`scrcpy ≥ 3.0`、`minSdk 30`、`Python 3.10+`

不用审：纯定性表述（"显著更快"、"两个数量级"这种只要有对应的两个数就行）、
明显是示例的数字（协议示例 JSON 里的 `"ms": 12`）。

## 4 · 每条断言要填的表

**这是本任务的主交付物。** 一行一条断言，不要合并、不要省略。

| # | 文件:行 | 断言原文 | 出处（file:行 + 原文引用） | 结论 |
|---|---|---|---|---|
| 1 | `README.md:96` | `导航类动作 … 0/20` | `E11-RESULTS.md:52` 主表 `nav true 20 0 0%` | ✓ 一致 |
| 2 | | | | |

`结论` 只能是三个值之一：

- **✓ 一致** —— 出处找到了，数字对得上
- **✗ 不一致** —— 出处找到了，数字对不上。**必须写清两边分别是什么**
- **⚠ 找不到出处** —— 翻遍了实验报告和原始数据都定不了它从哪来

> **「⚠ 找不到出处」不是失败，是本任务最有价值的产出之一。**
> 一个没有出处的数字和一个错的数字一样危险。**不要为了让表好看而硬凑一个出处。**

## 5 · 什么可以改，什么只能报

**可以改**（在 `audit/n1-numbers` 分支上直接改）：

- 结论为 **✗ 不一致**，**且**你能贴出出处的 `file:行 + 原文` —— 改成出处的数字

**只能报，不许改**：

- 结论为 **⚠ 找不到出处** —— 只写进表里
- 出处**自相矛盾**（两份实验报告给了不同的数）—— 写进表里并**同时列出两个出处**，
  不要自己判哪个对
- 任何需要重新解释结论、而不只是换个数字的地方 —— 写进表里，标「需人工决定」

**每一处改动都要在表里对应一行**，并且 commit message 里能追到。

## 6 · 已知陷阱

1. **同一个数在多个文件里出现，可能只有一处是对的。** 找到一处不一致后，
   `grep` 一遍全仓库看还有没有别的副本。
2. **「15 条 Kotlin 测试」这类总数会掺水** —— 实际是 8（LocatorResolver）+ 5（treeHash）
   + 1（ProbeMock 探路）+ 1（模板 stub）。总数没错，但用它描述「覆盖」就是夸大。
   **遇到「N 条测试覆盖了 X」这种句式，要同时核对 N 和「覆盖了什么」。**
3. **实验报告之间有更正史**（E9→E10、E8→E15、E10→E11、E13→E17）。
   引了**被推翻的那一版**是最常见的错误形态。核对时看清楚：
   这个数字的出处，是不是已经被后面的实验取代了？
4. **`docs/随手记.md` 是未整理的原始草稿**，不作为出处，也不要审它。
5. **别改 `.py` / `.kt` 的代码。** 注释里的数字可以改，
   但凡改动会影响一行可执行代码，停下，写进表里标「需人工决定」。
6. **改完注释要重跑一次测试**（`python -m unittest discover -s tests -q`），
   确认你没手滑动到代码。**把输出贴进报告。**
