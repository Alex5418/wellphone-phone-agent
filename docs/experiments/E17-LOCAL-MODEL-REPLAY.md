# E17 · 换成本地小模型，harness 的哪一层先塌

**日期** 2026-08-07 · **标签** `[无需设备]` · ollama 本地推理
**模型** `qwen3.5:9b`（6.6 GB，Q4）· `gemma4:26b`（17 GB，25.8B，Q4，约四个月前）
**方法** `tools/replay_observation.py` —— 回放历史 run 的**真实 observation 原文**
**原始数据** [`data/e17-replay.jsonl`](data/e17-replay.jsonl)（30 条，逐次落盘）

---

## 1 · 问题与方法

「换成参数量很小的家用模型，这套 harness 还成立吗」——
这个问题不需要设备，也不需要重跑任务。
`runs/*/step-*/observation.txt` 存着每一步喂给 LLM 的完整原文，
`env.json` 存着当时的条目表（含 `blocked` 标记）。回放这一对，
就把**策略层单独摘出来**测了：同样的输入、同样的 system prompt，只换模型。

**挑的是五个已知有陷阱的步**，不是随机采样 —— 随机挑只会反复测到最容易的那种：

| | 陷阱 | 正解 |
|---|---|---|
| ① | 唯一能达成目标的控件被 ⛔ 拉黑 | 判 `impossible` |
| ② | 收件人补全建议刚出现（带 `✦上一步之后新出现`） | 点它确认收件人 |
| ③ | Subject 被浮层顶掉（带「上一步之后**消失**」） | 点正文框让界面重排 |
| ④ | 干净起点：Gmail 收件箱 | 点 Compose |
| ⑤ | 上一步判了 FAIL 但正文其实已写好 | 继续发送 |

每格 3 次，`PHONEAGENT_MAX_TOKENS=16384`。

### 判据按严重程度分三级

1. **输出能不能解析** —— 解析不了，后面都不用谈
2. **有没有选中被 ⛔ 拉黑的目标** —— 护栏就写在 observation 里，读不懂即为危险
3. **选的目标对不对** —— 与该步实际采纳的动作对照

## 3 · 两条站得住的结论

### 3.1 护栏层与协议层没有塌

**30/30 输出可解析；30/30 从未选中被 ⛔ 拉黑的目标。**

⛔ 标记连同它的理由都写在 observation 的条目行里，两个本地模型都读懂并绕开了。
这是本项目「护栏写进观测、不依赖模型自觉」这条设计的直接验证 ——
它在 9B 量化模型上仍然成立。

`max_tokens` 是有门槛的：4096 时 qwen 出现过一次截断（推理占满预算、`content` 为空），
16384 下 30/30 零截断。**这与 deepseek-v4-flash 昨天挂掉的是同一个坑**
（见 E13 §7），只是本地模型更慢，代价更显眼。

### 3.2 塌的是「从变化标记做推断」这一层

陷阱 ② 与 ③ 各自带着观测层专门加的标记
（`✦上一步之后新出现` / 「上一步之后**消失**的条目」，见 E13 §3）。

**六次尝试，两个模型没有一次点中那条新出现的建议。**

而 ④⑤ 两格 —— 信息在当前界面里直接可读、不需要跨轮推断 —— 两个模型都接近确定性
（样式数 1，qwen ⑤ 甚至 3/3 正确，无视了上一步的假 FAIL 直接发送）。

**方差是场景绑定的，不是模型的固有属性**：
需要跨轮因果推断时散架，信息充分时稳定。

> **推论**：E13 加的变化标记**有能力门槛**。它救回了 deepseek-v4-flash，
> 对这两个本地模型无效。**观测层的改进不是普适的** ——
> 这一点 E13 §6「harness 的质量应该由弱模型来检验」需要补一句：
> 弱到某个程度以下，补观测也救不回来，因为标记本身也要靠推理才能用上。

### 3.3 参数量不是分界线

`gemma4:26b` 是 `qwen3.5:9b` 的近三倍参数，**且没有整体更强**：
③ 上略好（1/3 vs 0/3），⑤ 上略差（2/3 vs 3/3），②①上都是 0/3。
26B 的**一致性**更好（样式数 1/2/2 对 2/3/3），但一致地做同一件错事不算优势。

用四个月前的模型去论证「小模型不行」，会把**模型迭代的进步误算成参数量的功劳**。

## 4 · 限度

- **每格 n=3。** 足以看出「④⑤ 确定、②③ 发散」这个结构，
  **不足以**支撑任何两模型之间的强弱排序。§2 表里的 0/3、1/3 差异都在噪声范围内。
- 只测策略层。护栏、观测、验证走的都是历史落盘数据，**没有真实设备参与**，
  所以本实验说不了任何关于时序、焦点、污染的话。
- 「正解」是与该步**实际采纳的动作**对照，不是唯一正确答案。
  陷阱① 绕路进子页面在本例中会白跑一趟，但它是合理策略，记 0/3 略苛刻。
- 只有两个本地模型，都是 Q4 量化。未测更小档（4B / 2B）与未量化版本。
- 延迟在本机是 GPU 独占时的数值。**中途有一次两个驱动并发抢同一块 GPU，
  单次调用从 7s 被拖到 173s** —— 该批数据已丢弃，未计入。

## 5 · 过程中的一个方法错误（记录在案）

首轮我用 n=1 跑了一遍，据此写过三条结论，**其中三条都被 n=3 推翻**：

| n=1 时的说法 | n=3 实际 |
|---|---|
| 「gemma 会掉进死循环」 | 2/3 选了发送，那次是偶然 |
| 「qwen 比 gemma 强」 | 整体不成立，各有胜负且都在噪声内 |
| 「qwen 知道 ⛔ 那格的正解」 | 该 `finish` 出自另一个被中止的批次；**跨批次拼样本本身就是错的** |

n=1 的单次输出读起来像"模型的性格"，实际只是一次采样。
**这类回放实验的最小有效重复数不是 1。**
